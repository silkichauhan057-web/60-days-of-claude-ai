07 How the stop-check governs information flow
Each round follows the same information path: Evaluator reads the current draft plus the full rubric (the Planner's requirements/tests) and produces a literal score + written evaluation. That score is compared to the previous round's score to compute a delta, which is checked — in order — against three conditions: (1) plateau, two consecutive rounds improving by less than the delta threshold; (2) threshold, the score crossing the target set in the sidebar; (3) hard cap, a safety fallback so the loop can never run forever. If none fire, the round continues: Critic receives the same draft plus the Evaluator's report and produces a focused, literal critique. Improver receives the draft, the evaluation, and the critique, and rewrites the code. Memory Manager then distills what was learned this round into a short, persistent note that is prepended to every future Evaluator/Critic/Improver call — so later rounds don't repeat earlier mistakes. The new draft becomes next round's input to the Evaluator, closing the loop. If a condition fires, the loop breaks immediately and branches to the Final Reviewer, who receives the full history (every score, critique and memory note) and produces the polished final code plus a sign-off — never a hardcoded template, always a live call.
